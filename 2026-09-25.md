
## 78359db: Actual Service Call Cost is editable (as an adjustment)

**Request:** owner wanted to correct the Actual Service Call Cost on an SO, and asked how edits interact with parts/labor/expenses added later. Owner chose the adjustment model over a frozen override.

**How it works:** pencil on the cost card; typing a total stores only `Job.costAdjustment = typed - calculated` (+ optional `costAdjustmentNote`). `serviceCallCostBreakdown` now returns `calculated`, `adjustment`, `total = calculated + adjustment`, so later parts/labor/expenses still add on top. Remove writes `0` / `''` (not undefined) so the clear survives the sync merge. Site transfers stay at the flat fee, not editable. Billing card breakdown shows `+/- adjustment`; SOW report picks it up via `actualServiceCallCost`.

**Files:** `lib/woHelpers.ts`, `components/ServiceOrderPanel.tsx` (`ActualCostCard`), `components/Billing.tsx`, `types/index.ts`, `__tests__/serviceCallCost.test.ts`.

**Verified:** build + 1041 tests; live `version.json` sha 78359db; `/api/users` 401; "Edit actual service call cost" found in the served `ServiceOrderPanel` chunk. Not click-tested (needs login).

**Pattern:** a manual correction to a derived number is stored as a delta, so the derivation keeps working.

**Follow-up:** owner to decide whether editing should be admin-only (today anyone who can open the SO panel can edit, same as Parts & Labor).

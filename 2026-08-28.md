# 2026-08-28

## INCIDENT: production Vercel project deleted, app down ~11h+

### Symptom
`solarflow-dashboard-sooty.vercel.app` returned `404 DEPLOYMENT_NOT_FOUND` for every path,
including `/version.json`. Whole app unreachable for staff and contractors.

### Root cause
The Vercel project `solarflow-dashboard` (`prj_NzYDpnCcGvZW9pvN639W5c2eCiok`) was **deleted**.
Its production alias and ALL its environment variables died with it. Not a bad build, not a
stale deploy, not the Hobby function cap: the project itself was gone.

### The red herring that cost time
`vercel ls` printed:

    Your Project was either deleted, transferred to a new Team, or you don't have access to it anymore.

That message is about the **linked project** in `.vercel/project.json`, but it reads like a
**team access** problem, and the CLI then silently falls back to listing a different scope.
`vercel teams ls` showed only `cesarajurado-9599s-projects`, which appeared to confirm the
team was lost. It was not. When the replacement project was created, its `orgId` came back as
`team_pTe4xJXrqzDbQyEvguzmGMmO` -- the SAME org id as the "inaccessible" one. That org id IS
the personal scope. Access was never lost.

**RULE: on a Vercel "no access" error, create/link a throwaway project and read back its
`orgId` before concluding anything about team membership.** Do not trust the error text, and
do not trust `--scope <id>` appearing to fail; it falls back silently.

Wasted effort: `vercel login` was run twice, which reused the existing browser OAuth session
and re-authenticated the SAME account both times, appearing to "fail" while actually working.
**A `vercel login` that reuses a browser session is a no-op. Sign out in the browser first, or
pass the email explicitly.**

### Recovery
1. Created new project `solarops`, linked to GitHub `cexdance/SolarOps` (auto-deploy restored).
2. Re-added env vars from scratch. `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` are BUILD-TIME
   and the client throws without them (`src/lib/supabase.ts` reads them via bracket notation
   `import.meta.env['VITE_SUPABASE_URL']`, which is why a `grep import\.meta\.env\.[A-Z_]+`
   found nothing -- **grep both dot and bracket access**).
3. First deploy FAILED CLOSED on purpose: the strict `check-env` gate refused to ship without
   `SUPABASE_SERVICE_ROLE_KEY`. That guard did its job and prevented a silently broken deploy.
4. Trello creds recovered from local `solarflow-dashboard/.env.local` and re-set under the
   SERVER-ONLY names `TRELLO_API_KEY` / `TRELLO_API_TOKEN` instead of the old `VITE_`-prefixed
   ones. This incidentally closes the long-standing latent bundle-exposure item.
5. Service role key supplied by user. Used the **legacy `service_role` JWT**, NOT the new
   `sb_secret_` format: `api/` code makes raw PostgREST calls with
   `Authorization: Bearer ${SERVICE_ROLE_KEY}`, which expects a decodable JWT.
6. `vercel --prod --yes` from **repo root**. Verified `version.json` sha = `fd16528` (real
   commit, not `local`) and `/api/users` returns 401 JSON, not a 404 page.

### Production URL: UNCHANGED
**https://solarflow-dashboard-sooty.vercel.app** -- RECLAIMED. The delete freed the hostname and
`vercel domains add` reattached it to the new project, so no bookmarks broke.

GOTCHA: `vercel alias set <deployment> <host>` reported Success but 302d every request to
`vercel.com/sso-api` (a deployment alias inherits Vercel Authentication). `vercel domains add`
makes it a PRODUCTION domain, which is exempt. `solarops-two.vercel.app` also resolves.


### Data
NO DATA LOSS. Supabase is a separate service and was untouched throughout; live job queries
succeeded during the outage.

### Follow-ups

after the client name."

**Change** (`solarflow-dashboard/src/components/ServiceOrderPanel.tsx`): the `US-XXXXX` chip

    SO-2608-56003  [Completed] [Monitoring]
    US-15667 Todd Farley Case #7021404
    9143 CALOOSA RD, FORT MYERS, FL

**GOTCHA that drove the markup:** the three parts are ONE inline text run separated by explicit
`{' '}` text nodes, NOT flex children. JSX strips the newline between sibling elements and a
flex `gap` is not a character, so a drag-select over flex children copies
`US-15667Todd Farley`. Verified in a real browser before shipping: selection now yields exactly
`US-15667 Todd Farley Case #7021404`, host height 25px = one line, `truncate` still ellipsizes.
**RULE: when the point of a layout is COPY-PASTE, verify `getSelection().toString()`, not just
how it looks.**

**PowerCare case number source:** `rmaEntries[].caseNumber` (written by `RmaCreateModal.tsx`)
with a regex fallback over `serviceReport` + `notes`. Measured live first: **16 PowerCare jobs,
0 with a structured caseNumber**, and the only case number anywhere in the data is
`PowerCare Case #: 7021404` typed into Dubois's report text. Without the fallback the feature
would render nothing for every existing record. Marked `ponytail:` - delete the fallback once
case numbers are entered through the RMA modal.

**Verification:** `pnpm build` clean, 608/608 tests pass. Live sha `cb6352d`. `/api/users` +

## e951907 - Move to Client claims its number in the client registry sheet

Deployed and verified live (`sha: e951907`, `builtAt: 2026-08-28T23:23:37Z`).

### What changed and why
The consecutive `US-1XXXX` numbers live in the "Conexsol Client List" Google
Sheet, tab `MAIN LIST ` (note the trailing space). Nothing kept them in step
with the CRM: `handleConvertLead` just copied whatever `clientId` the SolarEdge
import had left on the job, and the sheet's Name column was maintained by hand.

"Move to Client" now POSTs to a Google Apps Script web app bound to that sheet.
It stamps the client name onto the row for the number the lead already carries,
or claims the first row whose Name cell is blank and returns that number. When
the pre-allocated run is exhausted it appends `max + 1`.

### Files
- `scripts/client-registry.gs` (new) - the Apps Script. `pickRow_` is pure so
  `demo()` can self-check it; `doPost` does the sheet I/O under a `LockService`
  script lock.
- `solarflow-dashboard/src/lib/clientRegistry.ts` (new) - one fetch.
- `solarflow-dashboard/src/components/Jobs.tsx:741` - `handleConvertLead` is now
  async and claims the number before creating the Customer.

### Deployment state
- Apps Script project bound to the sheet, deployed as a Web app, Version 2,
  Execute as Me, access Anyone.
- `VITE_CLIENT_REGISTRY_URL` set in Vercel **production** and **development**,
  and in local `.env.local`. **Preview is NOT set**: `vercel env add ... preview`
  loops (it demands a git branch, then rejects both suggested forms). Preview
  builds therefore skip the sheet call and convert leads the old way.

### Live test results (against the real sheet)
1. lookup with the same name -> `{clientId:"US-15015", name:"Daniel Matos Residence"}`, idempotent.
2. different name on a used number -> `{taken:true}`, **sheet not modified**.
3. unknown number -> error, no fall-through.
4. claim next free -> wrote `US-15017`. Test value removed from `C4` afterwards.

### Patterns worth reusing
- **A visible sheet tab label is not its name.** The tab reads `MAIN LIST` but
  is really `MAIN LIST ` with a trailing space, so `getSheetByName('MAIN LIST')`
  returned null and every request failed with a clean-looking error. Match on
  the trimmed, upper-cased name. Read tab names with
  `[...document.querySelectorAll('.docs-sheet-tab-name')].map(e=>e.textContent)`
  rather than trusting the screenshot.
- **A public sheet is readable without any auth** via
  `/gviz/tq?tqx=out:csv&gid=<gid>`. Used it to learn the column layout and to
  verify writes without touching the Sheets API.
- **Apps Script `/exec` beats the Sheets API here**: no service account key, and
  no new `api/` function (Hobby caps `api/` at 12). Post `text/plain` so the
  request stays CORS-simple; Apps Script does not answer preflight `OPTIONS`.
  The final response carries `Access-Control-Allow-Origin: *`.
- **Editing the script does not change what `/exec` serves.** You must
  Deploy > Manage deployments > pencil > Version: New version. Same URL, new
  code. Forgetting this reads exactly like "my fix did nothing".
- **`import.meta.env` needs bracket notation** under this tsconfig (TS4111),
  same trap as the 08-28 Supabase env work.

### Open follow-ups
- **The claim path fills the earliest hole, not the tail.** The first blank Name
  is `US-15017` (row 4), so the next converted lead gets 15017, not 15683. That
  keeps the numbering gap-free but is a real behavior choice: 11 blank rows are
  ahead of the tail. Confirm this is what the team wants.
- **Access is "Anyone"**, so anyone with the `/exec` URL can write a name into
  the registry. Same fail-open posture as the Trello webhook. A shared secret
  was offered and not yet decided on.
- The Apps Script project is still named "Untitled project".
- `/snap-ui` intentionally skipped: no visual change, this is behavior behind an
  existing button.

### What changed and why
Contractor Pay (`contractor-billing` view, rendered by `BillingModule`) already had a DAY/WEEK/MONTH/QTR/YTD/CUSTOM bar but no way to isolate one contractor. Added:

1. **Contractor dropdown.** Options are derived from the `contractorId`s actually present in the job list, not the full roster, so the select never offers a contractor with zero orders. Label resolution is `contactName -> businessName -> email -> id`. `Contractor` has no `name` field, that chain is the real fallback order.
2. **Filter applied in `allJobs`, not `filteredJobs`.** `filteredJobs` only feeds the rendered card list; `allJobs` feeds the `totals` reducer behind the profit / goal / pay-status tiles. Filtering in the wrong one would have shown one contractor's cards under the whole team's money.
3. **ALL timeframe button.** Two reasons: with a contractor selected you usually want their full history, and `getDateRange()`'s `custom` branch returns `customDateRange`, which starts `{start:'', end:''}`, so selecting CUSTOM before typing dates made `jobDate >= '' && jobDate <= ''` false for every row and rendered an empty board. ALL short-circuits before the date comparison.

### Patterns worth reusing
- **In any board with summary tiles, the filter belongs on the array the reducer consumes.** This file has two derived arrays a filter could plausibly go in, and only one of them reaches the money at the top. Check which array the totals read before adding a filter.
- **A date-range filter whose empty state is `''` fails closed on every row.** `'2026-08-01' >= ''` is true but `<= ''` is false, so a blank range renders nothing rather than everything. An explicit ALL that returns before the comparison is cheaper than special-casing empty strings.

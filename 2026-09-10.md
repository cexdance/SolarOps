### RULE: Vercel's Node builder only bundles what it can STATICALLY trace

After the ad5c9b9 outage I moved the report import to
`await import('./_dailyReport')` inside the cron branch. It deployed clean and
then failed at runtime:

```
Cannot find module '/var/task/api/_dailyReport' imported from /var/task/api/notify.js
```

A dynamic import is not traced, so the file was never emitted into the lambda
at all. `_notifyGuards` works precisely because it is a STATIC import; the
leading underscore only keeps a file from becoming a route, it does not keep it
out of the bundle. The same tracing gap, reaching a path OUTSIDE `api/`, is what
killed every branch of the endpoint in ad5c9b9.

Fixed in 4d7f67e by importing statically again, which is safe now only because
`_dailyReport` and everything it pulls in live under `api/` and do nothing at
module scope but declare consts and functions. `apiResilience.test.ts` globs
`api/*.ts` and asserts no import-time throw, which covers it.

**The lazy import still earned its place.** It contained the second failure to
the cron branch alone: `/api/notify` stayed 405 and @mentions kept working, so
this was diagnosed from a clean JSON error rather than a second outage.

### The pre-deploy gate for api/ changes does NOT catch this

`esbuild --bundle` + `require()` + call every branch catches import-time
throws, and it passed for both the broken and the working version. It cannot
catch a Vercel *tracing* difference, because esbuild inlines everything into one
file. The only proof for an api/ change is to call the deployed endpoint on
every branch immediately after deploy, which is now how this was caught twice.

## db61138: verbal quote approval keeps the order in Create Quote

**Deployed** `db61138`, live `v1.7.6.2+db61138.1789063151481`, `/api/users` returns
`401 {"error":"Unauthorized"}` (JSON, not a Vercel NOT_FOUND), so the serverless

### The problem
SO-2609-78916 (Taylor Williams, SITE-COMM) was moved to Scheduled because the
client approved the site visit quote verbally on the phone. That skipped the
Quote Sent stage rather than deferring it, so Daniel was never asked to raise
the paperwork and the card landed in Pending Completion, a column that asks
nothing of anyone. The client got no quote and nothing in the system knew.

### What shipped
One predicate everything reads, `needsFormalQuote = verbalApprovalAt && !quoteSentAt`
(`lib/woHelpers.ts`):

1. `verbalApprovalAt` / `verbalApprovalBy` stamped in `App.handleUpdateJob`, the
   single save choke point, so the kanban drag, the SO panel and the
   auto-dispatch branch are all covered by one check. Fires only on the
   TRANSITION into `quote_approved` / `scheduled` / `in_progress` with no quote
   sent. PowerCare, site transfers and service-account expenses are excluded,
   they have no quote step.
2. Daniel notified once via `notifyAdminForVerbalApproval` (same @mention path as
   the ready-to-invoice notice), guarded by the stamp so dragging the card
   cannot re-send it.
3. `getBillingColumn` routes the card back to the CREATE QUOTE column with an
   amber "Verbal OK" badge and a "Send Formal Quote" button. Placed BELOW the
   money-column checks, so a completed / invoiced / paid order still reaches
   Ready to Invoice. Dispatch is untouched, the crew works it normally.
4. `ServiceOrderPanel` gets its own amber banner + Send Formal Quote button,
   because the workflow bar offers the NEXT stage and never the quote on an
   already-scheduled order. A catch-up quote stamps `quoteSentAt` and does NOT
   advance the stage.

### Patterns worth reusing
- **RULE: a stage that can be SKIPPED by a real-world event needs a debt marker,
  not a gate.** Blocking the move to Scheduled would have taught the office to
  backdate a fake "quote sent". Recording the skip and re-routing the card puts
  the work in front of the person who owes it without stopping the field work.
- **RULE: key the debt on an EXPLICIT stamp, never on a bare missing field.**
  `!quoteSentAt` alone would have dragged the whole historic backlog into
  Daniel's intake column (0 of 13 Quote Sent cards had `quoteSentAt` as of
  2026-07-28) and buried the cards that actually need work.
- **RULE: re-routing a card into a column means re-checking that column's own
  controls.** The CREATE QUOTE card's button and the panel's workflow bar were
  both written against the population that arrives there normally; neither
  offered a way to raise the quote on an order already past that stage.
- **Fixed underneath: nothing was ever writing `quoteSentAt`.** Neither quote
  preview path stamped it, which is why the field is empty across the backlog.
  Now stamped when the quote goes out, which is what lets the flag self-clear
  and also fixes Quote Sent card aging.
- **GOTCHA: adding a second entry to an `AGE_ANCHORS` chain demotes the first.**
  `cardAge` reports `exact: false` for anything past index 0, so putting
  `verbalApprovalAt` ahead of `createdAt` marked every ordinary New card's age
  inexact and broke `billingColumns.test.ts`. Reverted; older still means more
  urgent in an intake column.

### 1. Root cause of the drift (f5c7158)

13 cards moved in Trello sat in their old LL column; 22 had stale labels.
`mergeJobFields` picks each field by `fieldTimes[field]` (record time only
as a fallback). The webhook set `pipelineStage`/`labels` and bumped
`updatedAt` but **never wrote `fieldTimes`**, so the next browser holding the
prior version saw a tie, kept its stale value and pushed it back. Proven on
live records: every drifted job had a stage edit time older than its Trello
move (Zach Ross: moved 09-08, stage time 08-28); the one job with no entry
kept its move. `stampMirroredFields()` now stamps every webhook-written field.

**RULE: a server-side write into a record that clients merge PER FIELD must
stamp the per-field clock, or the first stale client silently reverts it.**
Bumping the record time is not enough. Test reproduces the bug with the Zach
Ross record and proves the fix in both merge orders.

### 2. One-time drift repair (data, no commit)

35 fixes, most-recent-wins per field: 15 Trello->LL, 18 LL->Trello, 2 union.
**Near-ties (under 2 min) cannot be ordered by two different clocks:** column
ties go to LL (09-03 rule), label ties take the union. Hicks is the case that
proved it: both sides stamped in the same minute, and the 09-03 note says
LL's un-convert was the intent. Many LL-wins labels dated 08-28..09-01, when
the token was still read-only: real edits that never pushed. Re-audit after
90s: **0 column, 0 label drift**, held. Alexis Crump Hernandez set to the new

## Lead Lobby stopped importing from Trello (fc48079, 07784f6)

**Symptom:** "LEAD LOBBY IS NOT UPDATING FROM TRELLO." Last import 2026-08-28.

**Root cause:** a new Trello list, `LOST TO COMPETITION` (`6a921054f4c77bfac810188f`),
was created ~08-29 at **position 0** of the "Conexsol Florida Services" board.
Trello's "Add a card" defaults to the leftmost list, so every new card went
there instead of into `Leads Services SolarEdge`. The webhook fired and
returned 200, `matchTargetList` found no target, and `backfillLeadJob` no-oped
on a job that had never been created. 5 leads never reached LL.

**Nothing was broken.** The webhook registration was `active: true`,
`consecutiveFailures: 0`; `HEAD`/`POST /api/trello-card` both 200; board id
allowed; credentials present. **RULE: a healthy integration with a healthy
endpoint and zero delivery failures can still import nothing, because the
"which list?" predicate is config, not plumbing. Diff the upstream board
against the config before touching either.** The tell was that the newest card
in the WATCHED list was 3 days old while the BOARD had cards from today.

### Changed

- `api/trello-card.ts`
  - `TARGET_LISTS` + `LIST_STAGES`: import from `LOST TO COMPETITION`.
  - `pipelineStage` is now MIRRORED from Trello, but **only on an event carrying
    `listAfter`**. Reading `card.idList` instead would apply a move the event
    never described (the card may have been dragged again before our fetch), and
    mirroring on every event would let a comment drag a card back a column.
  - **The bug the obvious version would have shipped with:** a move INTO a
    tracked list is BOTH a target match and a list move, so it takes the create
    path, and `upsertLeadJob` is create-if-absent, returning `'exists'` without
    writing. Dragging an already-imported lead into `LOST TO COMPETITION`, the
    single most likely action on that list, would have changed nothing in LL.
    Now `'exists'` re-enters the same `backfillLeadJob` mirror.
  - `labels` are a WHOLE-SET mirror now (was union-add-at-intake-only).
  - New `PATCH` branch: app -> Trello label push, `requireUser`-gated, board-id
    checked against Trello's own `idBoard`. On the SAME function because Hobby
    caps `api/` at 12.
- `solarflow-dashboard/src/lib/trelloLabelSync.ts` (new), wired into both
  `LabelPicker` call sites (`LeadPanel`, `ServiceOrderPanel`). Fire-and-forget.
- `types/index.ts`: new `lost_to_competition` stage, placed LAST. Trello has it
  first, which is exactly why cards landed in it by accident; repeating that

- `labelCatalog.ts`: added `Lost to competition`, `Vm+txt` (on the board, absent

- `src/__tests__/trelloMirror.test.ts` (new, 9 assertions).

### The echo-loop trap (worth reusing)

Bidirectional label sync ping-pongs forever if the two sides spell a label
differently. The live board has **`First Contact – Call Completed` with an EN
DASH**; `LABEL_CATALOG` uses a hyphen. Compared raw, each side reads the other
as changed and mirrors back, forever. `sameLabelSet()` compares by `labelKey()`,
duplicated server-side because `api/` cannot import from `src/`; a test pins the
two normalizers to each other. **RULE: a bidirectional mirror is only safe when
its equality test is the same normalization both writers use. Set equality, not
array equality: order and colour are not identity.**

## LL kanban -> Trello push, the headless arrangement (d367719)

**The arrangement the user described:** leads arrive by email. Anthony types
each one into Trello by hand and will not automate it, and he does not use or
trust SolarOps. The office works those leads in the LL kanban. So LL must be
the surface that moves the record, and Anthony's board has to follow it
without him doing anything. Trello stays his inbox; LL becomes the system.

### Changed

- `PATCH /api/trello-card` generalised from labels-only to a card push:
  `{ cardId, stage?, name?, labels? }`. **Only the fields sent are written**,
  which is what makes it safe to call on every save: a kanban drag cannot
  rewrite the card's name or labels as a side effect. One `PUT` carries a move
  plus a relabel, so Trello fires ONE `updateCard` back instead of two.
- **`STAGE_LISTS` is built by inverting `LIST_STAGES`**, never written out a
  second time, so the two directions of the mirror cannot drift. A test
  round-trips **every** entry of `PIPELINE_STAGES` through both maps. **RULE:
  an unmapped column does not error, it silently stops mirroring, and you find
  out days later when Trello is wrong. Assert the round trip, not the map.**
- **Name is pushed ONLY over a placeholder filename.** Anthony's cards arrive
  named `image.jpeg` because Trello fires `createCard` before the attachment
  lands, so naming them is the most useful thing this push does for him, and
  overwriting a name he typed by hand is the worst thing it could do. The
  client sends `clientName`, never `title`: `title` becomes `WO, <name>` on
  conversion, and pushing that would rename his card to internal jargon.
- **Hooked into `App.handleUpdateJob`, the single save choke point**, replacing
  the two per-control hooks from fc48079. Every LL edit path (kanban drag,
  LeadPanel, ServiceOrderPanel) already funnels through it, so one call covers
  all three and a control added later mirrors for free. **RULE: hook a mirror
  at the save path, not at the widgets, or the mirror's coverage is a list
  someone has to remember to extend.**
- `cardPatchFor(prev, next)` is pure, exported and tested. It returns
  `undefined` for the common case (costs, photos, scheduling), which is what
  keeps this off the ~95% of saves that have no card representation.

### Echo-loop analysis (all four paths terminate in one round trip)

1. Drag to a NON-target list -> `PUT idList` -> `updateCard` w/ `listAfter` ->
   backfill computes the stage already on the job -> `stageChanged` false ->
   no write.
2. Drag INTO a target list (`leads`, `lost_to_competition`) -> `matchTargetList`
   matches -> `upsertLeadJob` returns `'exists'` -> reconcile backfill with the
   same stage -> no write. **`notified` is 0 because notification fires only on
   `'created'`,** so pushing a card into the Leads list from LL cannot spam the
   office.
3. Label push -> whole-set mirror returns the identical set -> no write.
4. Name push -> `job.clientName` is no longer a placeholder -> `nameChanged`
   false -> no write.

### Notifications: already existed, verified, one honest gap

`notifyNewLead` already writes a `notifications` row per office user
(admin/coo/support) plus best-effort web push, and fires ONLY on a genuinely
new card. Verified live: 7 users notified per lead. The in-app bell already

like it worked.** `url` stays `/` with a comment saying why. **RULE: a link
nothing parses is worse than an honest generic link, because it stops anyone
from noticing the route is missing.**

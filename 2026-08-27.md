## Actual Service Call Cost on the SO panel + SOW report (a726667)

**Live:** `v1.7.6.2+a726667.1787836979810`, builtAt `2026-08-27T13:22:59.810Z`. `/api/users` returns 401 (not a Vercel NOT_FOUND), so the serverless functions built.

### What / why

Daniel needed a single number on a service order saying what the call ACTUALLY cost: labor plus any extra materials or expenses, and it had to appear on the SOW Completion Report above the Weather section.

The math already existed in the SO panel's Cost Breakdown (`totalCost = totalLabor + parts + mileageCost`), it just wasn't labeled that way, didn't include contractor-logged receipts, and the SOW report had no cost section at all.

### Files modified

- `solarflow-dashboard/src/lib/woHelpers.ts` — new `actualServiceCallCost(job, expenses)`. Pure; expenses are passed in so callers own where the contractor jobs come from. Mirrors the panel math exactly: base contractor pay (flat vs hourly) + extra labor line items + parts (line items, falling back to `job.partsCost`) + mileage (Powercare only, $0.54/mi) + non-rejected/non-draft contractor expenses.
- `solarflow-dashboard/src/components/SowDistributionModal.tsx` — new "Actual Service Call Cost" `<Section>` directly above Weather. Reads contractor expenses via `loadContractorJobs()` filtered by `(cj.sourceJobId ?? cj.id) === job.id`.
- `solarflow-dashboard/src/components/ServiceOrderPanel.tsx` — added `contractorExpenseTotal` memo, folded it into `totalCost`, added a "Contractor expenses" row when non-zero, and relabeled the bottom line "Total cost" -> "Actual Service Call Cost".

### Patterns worth reusing

- **Nothing new stored on `Job`.** The number is fully derivable from `lineItems` / `contractorPayRate` / `partsCost` / `travelMiles` plus the contractor job's expenses. A stored copy goes stale the moment any of those change and adds another whole-record-LWW clobber surface for no gain.
- **`formatCost`, not `formatMoney`.** `SHOW_MONEY=false`, so `formatMoney` would have silently rendered the whole feature as `-`. This is a cost the field typed in, which is exactly the case `formatCost` exists for. Third time this trap has been hit; the tell is "my new money row shows a dash".
- **Expenses read from the ContractorJob, never mirrored onto the admin Job.** Same reasoning as the existing `contractorAdditions` memo right above it: one writer, so a stale admin save can't clobber a field entry.
- **Shared helper over duplicated arithmetic.** The panel and the report now compute from the same function, so the two surfaces can't drift into disagreeing about what a job cost.

## Powercare mileage visibility + cost readout on the SO card (ed6fdb3, fd16528)

**Live:** `v1.7.6.2+fd16528.1787844066235`, builtAt `2026-08-27T15:21:06.235Z`. `/api/users` 401, functions built.

### What / why

Two follow-ups to a726667, same feature.

**ed6fdb3, Powercare mileage.** Daniel asked to "add the miles x $0.54 to the cost" on Powercare clients. It was already being added: `actualServiceCallCost()` shipped with `job.isPowercare ? (job.travelMiles || 0) * 0.54 : 0`, and the panel's Cost Breakdown had a Mileage row from the start. What was missing was PROOF on the SOW report, whose caption read "Labor, parts and logged expenses" and never mentioned mileage. On a Powercare job with miles logged the caption now reads `... · mileage 42 mi x $0.54 = $22.68`. Math untouched.

**fd16528, card readout.** The number was only reachable by opening Parts & Labor and scrolling to the Cost Breakdown. Added a read-only row on the Overview tab between Job Title and Service, per screenshot. The caption names only the components actually present (`Labor`, `+ parts`, `+ 42 mi x $0.54`, `+ expenses`), so a non-Powercare parts-free job just says "Labor".

### Files modified

- `solarflow-dashboard/src/components/SowDistributionModal.tsx` — `powercareMiles` const + mileage clause in the cost caption.
- `solarflow-dashboard/src/components/ServiceOrderPanel.tsx` — hoisted `baseLaborCost` / `mileageMiles` / `mileageCostLive` / `actualCallCost` to component scope; new readout block above the Service field; Cost Breakdown IIFE now consumes those instead of recomputing.

### Patterns worth reusing

- **"Add X to the total" often means "the total doesn't SHOW X".** The arithmetic was right on the first commit; the report just never said mileage was in there, so it read as missing. Check what the UI claims the number contains before changing what it contains. Cost of getting this wrong is double-counting.
- **A caption that lists fixed components lies on the jobs missing one.** Building the caption from what's actually non-zero keeps it honest, and doubles as a cheap debug readout: no `mi` clause on a job you expected to be Powercare means `isPowercare`/`travelMiles` is unset on that record.
- **Two surfaces rendering one number = hoist, don't copy.** The header readout and the Cost Breakdown both needed base labor and mileage. They now share one component-scope computation. Copying the arithmetic is exactly how a total and its own breakdown end up disagreeing.
- Computed from LIVE panel state, not the saved `Job`, so it tracks unsaved edits. The SOW report uses the pure `actualServiceCallCost(job, expenses)` helper because it only ever sees saved data.

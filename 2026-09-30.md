### What shipped (`api/trello-card.ts`, `importCommentEvent`)
- A comment becomes a `trello-cmt-<commentId>` activity entry (author + the comment's own date). Legacy `trello-comment-` counts as already imported.
- **Nothing in the payload is trusted.** The comment is re-fetched from Trello by id: real `commentCard`, allowed board. A delete needs the comment to genuinely 404 AND the record to already hold it.
- **Append only, edits and deletes included.** The client's `unionById` keeps the copy a browser ALREADY holds, not the newest, so an in-place rewrite never reaches a browser that loaded the old text and that browser pushes it back. An edit is a new entry keyed on comment + text hash; a delete is one note per comment with the original kept.
- **Echo guard.** `_trelloCustomerSync.ts` (d7be441) already POSTS SolarOps activity, audit, RMA and notes to Trello as marked comments. 661 of 717 "missing" comments were those echoes. `isSolarOpsEcho()` refuses them; the export side already refuses `trello-` ids, so the loop is closed both ways.
- Stamps `fieldTimes.activityHistory`. Also lands comments on service orders sent to Trello, not only leads.
- `?commentsOnly` lets the backfill replay without re-running the contact backfill (it can only do less work).

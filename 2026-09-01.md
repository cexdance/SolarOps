## 223ac66 - CSP blocked the client registry write ("Failed to fetch")

**Symptom:** "Move to Client" on a lead alerted `Could not update the client registry sheet: Failed to fetch. Nothing was converted.`

**Cause:** `claimClientNumber()` (`solarflow-dashboard/src/lib/clientRegistry.ts`) POSTs to the Apps Script `/exec` URL, but `vercel.json`'s `connect-src` never listed `script.google.com`. The browser killed the request before it left, so the `catch` reported a network error and correctly aborted the conversion. Nothing wrong with the script or the sheet.

**Fix:** added `https://script.google.com https://script.googleusercontent.com` to `connect-src` in `vercel.json`. Both hosts are needed: `/exec` 302s to `script.googleusercontent.com`.

**Files:** `vercel.json`

**Verified:** prod `version.json` sha = 223ac66, the live CSP header contains `script.google.com`, `/api/users` still 401s (functions built).

**Pattern worth reusing:** a third-party host added in code needs a matching `connect-src` entry, or it fails only in prod. `vite dev` sends no CSP header, so this class of bug is invisible locally. Same family as the 05-01 `recompressDataUrl()` CSP no-op.

## f3a1ba2 - production report emailed as plain text instead of the HTML report

**Symptom:** the client received an email whose whole body was "Please view the attached HTML report for your solar production summary. - Conexsol Service Team". No report, no attachment.

**Cause:** `handleSendReport` in `Customers.tsx` reads the SMTP password from `sessionStorage`. Settings wrote it there too, so it was gone in every new tab. With no password the send fell through to a `mailto:` fallback, and a `mailto:` body is plain text by spec, so the HTML report could never ride in it. The fallback's hardcoded sentence is exactly what the client saw. The SMTP path itself (`api/send-report.py`) was fine all along: it already attaches the full HTML as a `text/html` MIME part.

**Fix:**
- `Settings.tsx` - SMTP password now persists in `localStorage`. Reads fall back to the old `sessionStorage` value once so nobody retypes it; Clear removes both keys.
- `Customers.tsx` - same read order on the send path.
- `Customers.tsx` - deleted the `mailto:` fallback. Missing credentials now set `sendError` ("Email password not set for this session...") instead of opening a compose window that cannot carry the report.

**Files:** `solarflow-dashboard/src/components/Customers.tsx`, `solarflow-dashboard/src/components/Settings.tsx`

**Pattern worth reusing:** a silent fallback to a *less capable transport* is worse than an error. The send "succeeded" every time, so the failure only surfaced when a client mentioned the email looked empty. If path B cannot carry the payload path A carries, it is not a fallback, it is a bug with a friendly face.

**Second pattern:** `sessionStorage` for a credential means the feature silently degrades once per tab. Pick the storage lifetime to match the feature's lifetime, or make the missing-credential case loud.

**Tradeoff accepted by the user:** the SMTP password is now plaintext in `localStorage`, readable by any script on the origin. Upgrade path is recorded in a `ponytail:` comment at `Settings.tsx:136` - move the credential server-side per user.

**Follow-ups:** none blocking. No visual change shipped, so `/snap-ui` was skipped.

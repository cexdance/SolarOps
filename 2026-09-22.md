# 2026-09-22

## a46a6a4: a Xero quote acceptance moves the SO to Approved by itself

**Ask:** Daniel gets "Georgina Martinez has accepted quote QU-0460 for 500.00 USD" from Xero; the card should move Quote Sent -> Approved without a human.

**Why the email and not the API:** Xero publishes webhooks for contacts and invoices only, never quotes, and this app has NO Xero connection at all (`xeroConfig` defaults to `connected:false`, no tokens, no API code, no `app_data` row). Building the OAuth integration to poll quotes is a project; the email is the signal that already exists. Owner chose Gmail Apps Script over Zapier.

**The missing link was identification, not plumbing.** Nothing tied `QU-0460` to an order. New `Job.xeroQuoteNumber`, typed on the SO panel in a bar that shows while the order sits at Quote Sent (and afterwards only if a number was recorded).

**Endpoint rides `/api/notify`** (`action: 'xero-quote-accepted'`), because `api/` is at the Hobby cap of exactly 12 functions. Authenticated by `XERO_MAIL_SECRET` with the existing `safeEqual`, checked BEFORE the JWT branch since the caller is a script, not a user.

**Rules (`api/_xeroQuote.ts`, pure and tested):**
- Parses the SUBJECT only, tolerating any depth of `Fwd:`/`Re:`. The body is templated marketing text that gets re-wrapped in transit.
- Matches on the quote number alone, normalized for case and spacing.
- **Only an order at `quote_sent` moves.** A re-sent or late-forwarded email must never drag a scheduled, completed or invoiced order backwards. Already-approved is a 200 no-op so the script stops retrying.
- Server write stamps `fieldTimes` (status, woStatus, quoteApprovedAt, auditLog) or the first stale browser reverts it.
- No match: 404 and a log line, never a guess. A wrong card moving is worse than a manual move.

**Scale trap caught pre-ship:** the first version scanned every `job:` row. PostgREST truncates at max-rows with `error === null`, so that scan would have quietly stopped finding orders as the table grew (292 jobs today). Now filtered server-side to `value->>xeroQuoteNumber=not.is.null`, a handful of rows, with matching still done in code so hand-typed spacing is forgiven.

**Script:** `scripts/gmail-xero-quote-accepted.gs`, with setup steps in its header. Posts the subject line only, no body, no attachments, no customer addresses. Idempotent through a `Xero/Sent to SolarOps` label; retries only on 401/5xx.

**Files:** `api/_xeroQuote.ts`, `api/notify.ts`, `scripts/gmail-xero-quote-accepted.gs`, `src/types/index.ts`, `src/components/ServiceOrderPanel.tsx`, `src/__tests__/xeroQuoteAccepted.test.ts`. 1036 tests, build OK.

**Live verification** (after `vercel env add XERO_MAIL_SECRET production` + a manual `vercel --prod` from the repo root, since env vars only reach NEW deployments): wrong secret 401, unknown quote number 404, non-acceptance subject 400, `/api/users` still 401. Not yet proven on a real acceptance: no order carries a quote number yet.

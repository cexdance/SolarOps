## 209bec6: creating the follow-up quote approves the visit

**Deployed** `209bec6`, live `v1.7.6.3+209bec6.1789580656213`. `/api/users` returns
401 JSON. Deployed bundle checked across all 106 JS chunks: the new visit copy is
in `ServiceOrderPanel-*.js` and "Record quote approval" appears in none.

### The problem
A follow-up visit (8c163ca) needed Daniel to create its quote AND then press
"Record quote approval" with a typed reference. He was approving his own quote.
Until he did, the panel blocked advancing with "Record quote approval or mark the
follow-up included in Visits first."

### What shipped
- `App.handleUpdateJob` writes `currentVisit.approval = 'approved'` (decidedBy,
  decisionReason "Quote created") on the admin save that carries `quoteSentAt`.
  Written onto `currentVisit`, not inferred, because the contractor view copies
  `currentVisit` but has no `quoteSentAt`, and the server `pendingVisit()` reads it.
- Office gates (panel workflow + save, Billing drag + Approved) use the new
  `visitAwaitingQuote` = pending AND no `quoteSentAt`, so the save that records the
  approval is not blocked by the gate it clears. Contractor gates are unchanged.
- VisitWorkspace: "Record quote approval" button removed. "Included, no additional
  charge" stays, it is the only case with no quote.
- Panel: a Create Quote control for a pending visit at ANY stage, landing the order
  at Quote Sent. A finished first visit can leave the order at Completed, where the
  workflow button offers Invoice and never the quote.
- Test `visitQuoteApproval.test.tsx`. 1003 tests pass.

### Rule
**RULE: when the artifact IS the decision, record the decision from the artifact.**
A separate confirm step for something the same person just produced is a second
click that can only be forgotten, and here it blocked the whole order.

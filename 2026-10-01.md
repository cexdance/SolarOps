## d71e6a0: SolarOps comments on Trello are now short and readable

Owner: the comments SolarOps posts to Trello "do not make a lot of sense. Clean them up and leave something the user can understand quickly. If we need to tag that it's coming from SolarOps, keep it under 1 line with date and author."

### What was on the board (661 SolarOps comments, written by `api/_trelloCustomerSync.ts`, d7be441)
| Category | Count | Decision |
|---|---|---|
| Automatic "Work order SO-x updated, ... · new", no author | 315 | removed |
| Audit entries (85 just "Fields updated") | 139 | removed |
| Field-edit diffs ("Updated: Address: ...") | 41 | removed |
| Record notes (27 = the lead email already in the card description) | 67 | removed |
| Raw JSON audit dump | 1 | removed |
| Real notes (calls, emails, call summaries) | 80 | kept, reformatted |
| RMAs | 18 | kept, condensed |

Owner chose "keep notes + RMAs, remove the rest". Everything removed still lives in SolarOps.

### New format
- Note: its text, a blank line, then one tag rendered by Trello as `SolarOps · Cesar Jurado · Sep 30, 2026`. "(Admin)" and "Not recorded" dropped; date in America/New_York.
- RMA: `RMA 7294738 · Site Transfer · SolarEdge · Pending`, case number only when it differs, no address/customer (on the card already), no dollar amounts.
- The sync's identity marker moved INSIDE the tag's link URL (`#so-activity-<id>`), invisible on the board. The finder also matches the legacy full-line marker, so the next sync rewrites old comments in place: no duplicates.

### Echo safety (the part that could have gone wrong)
Every rewrite fires Trello `updateComment`, which the 08529eb importer re-fetches. If the importer did not recognise the new marker, each rewrite would land back in SolarOps as an "Edited in Trello" activity. `SOLAROPS_MARKER` is now defined beside the writer and imported by `isSolarOpsEcho`, so the two cannot drift. Verified live: rewrote one card (Wade Stanfield) first, waited for the webhook, **0** echo entries.

### Cleanup run
`scripts/cleanup-trello-solarops-comments.mjs --apply`: runs the REAL sync (compiled) for the 42 linked customer orders to rewrite keepers, then re-reads the board and deletes only bookkeeping categories, so a keeper whose rewrite failed is never deleted. Throttled to Trello's 100 req / 10 s.

### Tests
7 new format/behaviour tests (incl. in-place rewrite of a legacy comment, no duplicate, idempotent second run). Full suite 1071/1071.

### Gotcha worth keeping
`git stash --keep-index` to verify a committed-only build leaves UNTRACKED files in place. Another session's untracked `phoneLinks.test.tsx` then ran against its stashed-away `PhoneLink.tsx` and "failed" 3 tests. Not a regression; the tree intact is green, and CI never sees untracked files.

## ed27c19 - client number sheet mirror moves to the server

Deployed and verified live (`ed27c19`, `builtAt 2026-10-01T12:48:46Z`).

### Symptom
Assigning `US-15715` (Ron Devilliers) showed a modal mid-save: "US-15715 is
assigned, but the registry sheet could not be updated (NetworkError when
attempting to fetch resource.). The nightly check will fill it in."

### What was and was not broken
The number WAS assigned (Postgres owns them). Only the sheet mirror failed, and
the nightly check fills blank rows, so nothing was lost. What was wrong was the
write path and the severity of the message.

Ruled out before changing anything:
- CSP already allows `script.google.com` AND `script.googleusercontent.com`.
- The `/exec` endpoint returns 200 in ~3.5s from a server, with `ACAO: *`.
- The 302 redirect to `script.googleusercontent.com` also carries `ACAO: *`,
  so it is not the Firefox-strict-CORS-on-redirect case either.

Nothing in our deployment explained it, which IS the finding: the browser was
making a THIRD-PARTY request, so it depended on that person's extensions,
tracking protection and network. A cross-origin call the browser does not
control is not a dependable write path.

### Fix
The sheet write now goes through `/api/notify` (`action: registry-mirror`),
behind the JWT check already there, so it is same-origin and no browser setting
can block it. On the existing endpoint because `api/` is at the Hobby cap of 12;
placed before the mention rate limiter, which is not its quota.

The warning is a `console.warn` now, not a modal: a lagging mirror is not worth
interrupting someone mid-save when the nightly audit fills it in.

### Verified live
- Unauthenticated POST to the proxy -> **401**.
- From the production page with a real session: stamp `US-15716` -> 200,
  release -> `released: true`, malformed id -> 400 with a readable message.
- Sheet after: `US-15715` Ron Devilliers, `US-15716` blank again (next free),
  701 named rows, no test row left behind.
- `tsc -b` clean, build green, **1077 tests**.

### Patterns worth reusing
- **A browser's cross-origin write is a dependency on the user's browser
  settings.** When a call works from every server and fails for one person with
  no server-side explanation, stop debugging CORS and move the call behind your
  own origin.
- **Match the severity to who can act.** A modal belongs to something the person
  must decide; a self-healing lag belongs in the log.
- Vitest: a mock that throws or rejects inside the test file can surface as an
  unhandled error and fail the test for the wrong reason. Drive the same catch
  with a realistic non-ok response instead.

### 1. Lead Lobby fully removed (commit 9cfbbba)

The multi-state pipeline already lives on the S1 board inside Service Orders, and Trello intake lands there directly, so the separate Lobby screen was redundant.

- **S1 board tab renamed to `LL`** (Jobs.tsx button label + title; internal view key stays `'tryout'`).
- All 5 `'lobby'` references removed: the lazy `LeadLobby` import + `case 'lobby'` route (App.tsx), the nav item + both customers-parent-active refs + the now-unused `Inbox` icon import (Layout.tsx), and `'lobby'` dropped from the sales-role allowlist.
- `components/LeadLobby.tsx` deleted (~1900 lines; nothing imported its exports).
- **Webhook (`api/trello-card.ts`) is now JOB-ONLY.** Removed `upsertLead` + `backfillLead` (the two lead-store writers) and the dead `CRM_KEY`/`leadId`. A Job has no phone/email field, so contact info (phone/email/address) now rides in the **job notes**, or the team couldn't call an intake lead. That also closed the same gap for every future Trello lead, not just migrated ones.

### 2. Dedup-safe live-data migration (5 of 63 leads)

The user's "avoid duplicates" instinct was decisive. Of 63 leads in `solarflow_crm_data`:
- 33 Trello leads already had their `job-trello-*` row (the webhook created both) -> skip
- 8 `closed_won` already converted to a customer -> skip (that IS the duplicate)
- 17 more phone-matched an existing customer -> skip (already customers)
- 3 internal duplicate leads (same phone, different lead id) -> collapsed
- **5 genuinely new** (Robert Rivas, Shoshana Kramer, alfredo alfonso, Sean Raines, Steve Carbone) -> migrated to `job:job-lead-<leadId>` rows, `pipelineStage='leads'`, phone + original status preserved in notes. Idempotent (keyed by lead id, skips if the job exists).

A naive "migrate all 63" would have created ~20 duplicate customer-cards.

**Backup:** table `_bak_crm_leads_20260808` holds the full `solarflow_crm_data` blob (verified intact post-deploy). The original leads blob was never mutated; the migration only INSERTed new `job:` rows. Post-deploy check: 5 migrated jobs, all `pipelineStage='leads'`, all `customerId=''`.

### 3. Excel + screenshot import in the Add Customer flow (commit e733890)

The two importers that lived in the retired Lead Lobby are restored as customer-creation tools. Both parse ONE record and prefill the Add Customer form for review (per the user's choice; not bulk).

- `lib/leadImport.ts` (new, pure + tested): `mapRowToContact` handles the SolarEdge "Site Main Contact / RMA" export plus generic header fallbacks (loose, case-insensitive); `mapVisionToContact` maps the `/api/parse-lead-image` response; `readFirstSheetRow` reads the first spreadsheet row. Phone normalized, warehouse "RMA State" ignored (defaults FL), empty fields dropped so a prefill never blanks a typed field.
- `components/ImportPrefill.tsx` (new): one reusable, source-toggled panel (`sources: ('screenshot'|'excel')[]`). Hands parsed fields to the parent via `onParsed`; the parent owns the merge onto its own formData.
- **Main Customers "+ Customer" modal**: added Excel (its existing screenshot importer was already present and left untouched).
- **Sales Customer Directory "+ Customer" modal** (`CustomerManagement.tsx`, `customers2`): added BOTH screenshot + Excel (it had neither).

### Patterns worth reusing

- Before deleting a component, confirm nothing imports its exports (`grep` for the export names, not just the file path). LeadLobby's `PREDEFINED_SOURCES`/`getSourceBadge` were used nowhere else, which made the delete clean.
- A customerless intake Job cannot hold phone/email (no such fields on Job); put contact info in `notes` or the record is un-actionable.
- The dedup keys that actually work here: `job-trello-<cardId>` existence, `convertedCustomerId` -> live customer, and normalized-phone match against existing customers. Name is too fuzzy to dedup on safely.

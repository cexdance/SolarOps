## Summary

Every close of this order from one browser (Cesar's Chrome, device `dev-1776283250266-0cj3by8`) was recorded in `change_log` but never written to `app_data`. That browser had marked the row "poisoned" after 3 failed pushes, and the app skipped poisoned rows forever: the only way off the list was a successful push, which a skipped row can never make. The skip was a console warning only, so the user saw the card move, then saw the next sync pull the old server copy back into Approved.

## Evidence

- `app_data.updated_at` for the row stayed `2026-08-17 14:31:33` while `change_log` kept receiving updates.
- Database ruled out: RLS policies only check `is_staff()` for `job:` keys; the two triggers only stamp `updated_at` and normalize RMA timestamps; the only constraint is the primary key. Other rows from the same device saved normally in the same minutes.
- Device correlation: across all of `change_log`, only 4 jobs have edits newer than their row, and every one came from `dev-1776283250266-0cj3by8`:
  - SO-2606-21481: 18 lost edits since 08-26
  - SO-2609-35193: 4 since 09-16
  - WO-2605-22249: 1 on 09-15 (landed 09-17 15:31, after the fix shipped)
  - WO-2605-89308: 2 since 08-07
- Code: `pushToSupabase` in `src/lib/syncEngine.ts` skipped `isRowPoisoned(key)` rows with `continue`, no `markClean`, no thrown error. `src/lib/outbox.ts` stored poison in browser `localStorage` (`solarops_poisoned_rows_v1`), cleared only by `clearRowPoison` on success. `getPoisonedKeys` and `resetAllPoison` existed but nothing in production called them.

**Inferred, not proven:** the poison entry itself. It lives only in that browser's localStorage, which is not readable from the server. The original 3 push failures around 08-26 (error text in the entry's `lastError`) are unknown; a session refresh race or network drop is the likely trigger. Fits all observations: per row, per device, permanent, silent.

## Fix (4e16c94)

- `isRowPoisoned` returns true only within 10 minutes of `lastFailedAt` (legacy entries fall back to `since`, so the stuck 08-26 entry released on the next push).
- A skipped row throws, so the outbox stays pending and the sync error banner shows.
- Tests: `src/__tests__/outbox.test.ts` covers cooldown release and re-arm.

## Repair (2026-09-17 16:55Z)

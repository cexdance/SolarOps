## Site transfer billing fix + Visits control reorder (fa67e8d, 92bf283)

Two user-requested fixes, pushed on top of `96dd674`:

**`fa67e8d` fix(billing): show the site transfer flat fee, not an hourly breakdown.** The Billing list-view card ran every job through the generic "labor hrs @ rate/hr + parts" line, including site transfers, which have neither. Combined with `formatMoney`'s SHOW_MONEY gate (always renders "-"), a site transfer showed as `- / 1 hrs @ -/hr + - parts`, meaningless. Site transfers now show `$120.00 / Site Transfer, flat fee` via `formatCost`, the same SHOW_MONEY-bypass already used for this figure in ServiceOrderPanel's Actual Service Call Cost. $120 is a fixed rate named openly in the creation flow (`Jobs.tsx` lead-conversion path), not a variable commercial figure, so showing it does not violate the platform-wide money-hiding policy. Verified live against a real order (Pedro Cordon, US-15681).

Also confirmed, no change needed: the "Generate Invoice" button on a site-transfer card in Ready to Invoice already worked exactly as wanted (`getBillingColumn` already routes site transfers there on creation; clicking it opens the SOW report, and Daniel's "Mark Invoiced" from inside it moves the card out).

Verified live against a real order (Jarrod Hollander, US-15397): Overview shows it after Scope of Work; Parts & Labor shows it pinned at top; toggle-back path unbroken.

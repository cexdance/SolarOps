## ROOT CAUSE: "Saved to Date" always blank = formatMoney hidden by SHOW_MONEY (8f92f4a / v1.7.6.0)

**The real bug (I got it wrong 3 times first, blaming stale browser cache).** `lib/money.ts` exports `SHOW_MONEY = false` (deliberate: hide the internal commercial layer, "financials live in Xero"). `formatMoney()` returns `MONEY_HIDDEN = '-'` whenever `SHOW_MONEY` is false. Every savings display in the Production tab + client report routed through `formatMoney(dollarsSaved,...)`, so the dollar figure was suppressed to `-` regardless of production value OR the grid rate. The 30-Day Production / CO2 / Specific Yield tiles format INLINE (no formatMoney), which is why they rendered while only "Saved to Date" showed `-`.

**Why my stale-cache theory was wrong:** I traced the minified tile to `yt>0?formatMoney(yt):"Loading…"` and assumed formatMoney returns the value. It does not, it returns `'-'`. The screenshot's `-` was the CURRENT build all along. Lesson: when a value renders through a formatter, read the FORMATTER, don't assume it's an identity function. The tile that differs from its siblings is differing for a reason, and here the reason was the shared formatter, not the data.

**Fix (8f92f4a):** scoped `fmtSavings(n) = \`$${Math.round(n).toLocaleString('en-US')}\`` in `Customers.tsx`, used for the 6 client-savings displays (on-screen Saved-to-Date tile, compact Est. Savings card, 2 chart-tooltip labels, preview + email report tiles). Bypasses `SHOW_MONEY`. Did NOT flip the global switch: quotes, revenue, contractor pay, and the service-order `amount` (line 4119) stay hidden via `formatMoney`. RULE: the utility-savings estimate is a homeowner-facing marketing number, not a Xero financial, so it is correctly OUT of the SHOW_MONEY blackout.

**Build/test:** `pnpm build` green, 479/479 tests. **Deploy:** live `sha 8f92f4a`, builtAt `2026-08-10T15:35:36Z`; verified built chunk carries `"$"+Math.round(e).toLocaleString("en-US")`.

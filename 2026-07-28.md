## DEPLOYED 12ba81b, Trello auto-import leads missing name and info

**Commit:** `12ba81b` fix(leads): backfill Trello leads imported before the card was ready
**Live:** v1.7.6.0+12ba81b, builtAt 2026-07-28T18:37:28.728Z (propagated in ~90s)
**Reported as:** Lead Lobby cards from the auto-import showing a blank name, `-` phone, `-` email.

### Root cause: a race, not a parse failure

Trello fires the `createCard` webhook BEFORE it finishes uploading the card's
image attachment and writing its description. The webhook therefore fetched a
bare `image.jpeg` card with zero attachments and an empty desc, so
`fetchFirstImageAttachment()` returned undefined, vision never ran, and the lead
was written blank. `upsertLead`'s create-if-absent rule then meant nothing ever
filled it in.

Proved it by decoding the timestamps out of the Trello object ids (first 8 hex
chars = unix seconds), comparing card id vs. its attachment id:

| Lead | attachment arrived | outcome |
|---|---|---|
| Dante Moricoli | +0s | imported fine |
| Gil Hyatt, Sergio Guerreiro, Michelle Anderson, Ed Chase, Maayan Zdroyevski | +1s | blank |
| Luis Quintero | +4944s (82 min) | blank |

**Trick worth reusing:** any Trello id encodes its creation time.
`new Date(parseInt(id.slice(0,8), 16) * 1000)`. That is what turned "vision is
broken" into "vision ran before the image existed" in one step.

Second, separate gap: a card with a REAL name in the title (`Osmel Rodriguez`)
skipped vision entirely (`if (nameIsFile)`), so it imported with a name but no
phone and no email.

### Fix (api/trello-card.ts)

1. **`parseLeadDesc(desc)`** reads the SolarEdge lead email's labeled lines
   (`First Name:`, `Phone:`, `Zip Code:`) straight out of `card.desc`.
   Deterministic, free, no Haiku call. Blank labels stay unset rather than
   becoming `""`. Phone is normalized to 10 digits or dropped.
2. **Precedence is now desc -> card title -> vision**, via `extractCardFields()`.
   Vision only fires when the cheap sources left a hole, which also closes the
   named-card gap.
3. **Backfill path.** `updateCard` / `addAttachmentToCard` / `commentCard` on a
   card whose `lead-trello-<id>` ALREADY exists now fills empty fields only.
   No list check needed: the lead existing is itself proof the card came from a
   tracked list. Also repairs the job row's placeholder `clientName` / `title`.
   This is what actually cures the race, and it beats a sleep-and-retry in the
   create handler: it costs nothing, and it handles the +82min case that no
   retry window could.
4. **HMAC verification**, opt-in via `TRELLO_API_SECRET`.
   `X-Trello-Webhook == base64(HMAC-SHA1(rawBody + callbackURL, secret))`,
   constant-time, length-guarded so a short header can't throw in
   `timingSafeEqual`.

### PATTERN: fill-empty-only is the safe shape for any re-import

Both the webhook backfill and the .mjs script only write a field when the
existing value is blank. The OLD script did `Object.assign(lead, patch)` with
vision output assigned unconditionally, which would have BLANKED `Osmel
Rodriguez` (a lead with a name but no photo to parse). A re-import that
overwrites is a data-loss bug waiting for its first run. Same family as the
whole-record LWW clobber rule.

### GOTCHA: a webhook that signs the body needs the raw bytes

Trello signs `rawBody + callbackURL`. Vercel's body parser re-serializes JSON,
so the reconstructed string will not match and EVERY delivery fails
verification. Needed `export const config = { api: { bodyParser: false } }` plus
a manual stream read. **Verified honored on this runtime**: POSTing `not-json`
to prod returns `{"error":"Body is not valid JSON"}`, which can only come from
our own `JSON.parse(rawBody)`. A defensive fallback to `req.body` is in place if
that ever changes, and it logs loudly rather than 400-ing the lead pipeline.

**Deliberately fails OPEN when the secret is unset.** Failing closed would take
the live lead pipeline down on any deploy where the env var was missing, which
is worse than the threat (spam lead rows, needs two unguessable 24-hex ids,
nothing destructive, touches no existing data).

Registered callback is `https://solarflow-dashboard-sooty.vercel.app/api/trello-card`,
which matches what the code derives from `x-forwarded-host`, so
`TRELLO_WEBHOOK_CALLBACK_URL` is an unused override.

### Data repair

`node scripts/backfill-trello-leads.mjs --apply` fixed all 7 broken leads.
Verified after: `still_blank = 0` of 17 `lead-trello-*` leads.

Recovered: Luis Quintero, Osmel Rodriguez (phone only), Gil Hyatt,
Sergio Guerreiro, Maayan Zdroyevski, Michelle Anderson, Ed Chase.

## DEPLOYED d2078e3, @mention dropdown could not reach half the staff

**Commit:** `d2078e3` fix(mentions): show every teammate in the @ dropdown and match on any word
**Live:** v1.7.6.0+d2078e3, builtAt 2026-07-28T20:51:38.045Z (propagated in ~75s)
**Reported as:** "inconsistency", cannot use @ to get Daniel inside a service call.

### Root cause: a silent truncation, plus two implementations

`MentionTextarea` capped its list at `users.slice(0, 8).slice(0, 6)`. There are
9 staff and **Daniel Matos is 7th alphabetically**, so a bare `@` in the Service
Order panel rendered Andrea, Andreina, Anthony, Carlos, Cesar, Cruz and stopped.
He was not hidden by a filter bug, he was never rendered at all.

The "inconsistency" was literal: `Customers.tsx` carried a SECOND, hand-rolled
mention dropdown with its own filter and **no cap** (`: users`). The same @
gesture therefore found different people depending on which text box you were in.

### The five defects

1. **Truncation.** Cap removed, list scrolls (`overflow-y-auto max-h-64`).
2. **Prefix-only matching.** The old filter tested `startsWith` against the whole
   name/username only, so `@matos` matched nobody. New `filterMentionUsers()`
   matches name, username and email local-part on any WORD start, then falls
   back to substring, with prefix hits ranked first so `@d` still puts @dmatos on
   top. Shared by both panels now.
3. **`activeIdx` out of range.** ArrowDown to item 8, then narrow the query to 1
   result: `filtered[7]` is `undefined` and Enter threw. Clamped via `safeIdx`.
4. **Portal outside-click.** The dropdown is portaled to `document.body`, so it
   is NOT a DOM descendant of the component. The document-level `mousedown`
   handler fired before the option's own handler and closed the list first, which
   is the "clicking a name sometimes does nothing" symptom.
5. **Stale anchor.** The list is `position:fixed` but only re-measured on
   `[open, value]`, so scrolling the WO panel modal stranded it where the
   textarea used to be. Now re-measures on scroll (capture:true, the panel
   scrolls, not window) and resize.

### RULE: a handle must survive the reader that parses it back

`handleFor()` is now the ONE place that decides a user's @handle, and it strips
the `(Admin)` role suffix that staff display names carry. The old fallback
produced `@danielmatos(admin)`; parens fall outside `/@([\w.]+)/`, so
`parseMentions` could never resolve it and **the mention silently notified
nobody**. Any generated identifier has to be legal input to its own parser.

Writing the test caught a 5th case I would have shipped: a hand-typed
`@danielmatos` (no role suffix) also resolved to nobody. `matchHandle` now tries
the paren-stripped name too.

### Verification

- `src/__tests__/mentionMatching.test.ts`, 19 cases against the real 9-person
  staff list, incl. the 7th-of-9 regression and a handleFor -> parseMentions
  round-trip for every user.
- `npm run build` green (it caught a TS7030: the measure effect's early return
  needed an explicit `return undefined` once the other path returned a cleanup).
- Full suite 298/298.
- Browser: mounted the component in a THROWAWAY harness (`mention-harness.html`
  + `src/mention-harness.tsx`, both deleted after) so no auth was needed. Bare
  `@` -> 9 of 9 and scrollable; `@matos` / `@daniel` / `@dmatos` /
  `@daniel.matos` all -> Daniel; click inserted `@dmatos `; the clamp case
  selected instead of throwing.
- Prod bundle-string check: `overflow-y-auto max-h-64` present in the shipped

### GOTCHA: a hidden Browser pane pauses requestAnimationFrame

Pixel measurements taken while the preview pane was hidden were garbage
(dropdown measured at left:-13.5, width:26; a rAF-based settle loop timed out at
30s). Layout/paint is throttled in a background pane. Re-measure with the pane
visible, or use plain `setTimeout` and treat sub-pixel results as unreliable.
The scroll re-anchor was confirmed only indirectly this way (stale gap dropped
124px -> 13px), so it is the least-proven part of this commit.

### Files modified

  capture, so a refresh would produce byte-identical PNGs. Run it if you want

## Deploy 3: Billing kanban front stages, in-place service order, card aging (b075393)

Commit: `b075393` on `main`. Live at `v1.7.6.0+b075393.1785281895747`,
builtAt 2026-07-28T23:38:15Z, verified by the bundle-string check on
`assets/Billing-DYVh1qAc.js` (not just version.json).

### Why
Daniel Matos runs most of his day out of the Billing window, but the board
started at "Pending Completion". The two stages he actually works, quoting a
new service call and chasing a sent quote, had no home there.

### What changed

**Two new kanban columns** (`Billing.tsx`)
- `New` (blue): `!woStatus || woStatus === 'draft'`. Card carries a
  **Create Quote** button and the free-text scope so he can triage without
  opening anything.
- `Quote Sent` (violet): `woStatus === 'quote_sent'`. Shaped like the Invoiced
  card: `Awaiting Approval` chip plus an **Approved** button. Approve stamps
  `quoteApprovedAt`, sets `assigned`/`quote_approved`, and the card drops into
  Pending Completion. It comes back to Ready to Invoice on its own because
  `status === 'completed'` already wins over any `woStatus` in
  `getBillingColumn`. No new plumbing for the return trip.

**Service order opens over the board, not instead of it** (`App.tsx`)
- The panel is already `fixed inset-0`, so the fix was NOT a second
  `ServiceOrderPanel` (memory rule stands). Extracted App's ~60 lines of panel
  prop wiring into one `renderServiceOrder(backView)` helper with two call
  sites: `case 'jobDetail'` returns it as the whole view, `case 'billing'`
  renders it as a sibling of `<Billing/>`. Billing's `onJobClick` went from
  `handleViewChange('jobDetail', id)` to plain `setSelectedJobId(id)`, so the
  view never changes and Close lands back on the kanban with scroll intact.
- PATTERN worth reusing: **a `fixed inset-0` panel does not need its own view.
  Give the render helper a `backView` param and any view can layer it.** That
  is the cheap way to honor "open it in place" without duplicating prop wiring.

**Card aging, kanban only**
- `cardAge(job, col)` clocks each column off its own stamp: New→`createdAt`,
  Quote Sent→`quoteSentAt`, Ready to Invoice→`completedAt`,
  Invoiced→`invoicedAt`. Pending Completion (contractor's time), Paid and Costs
  Covered have no billing clock and never age.
- `ageTier(days)`: 0-2 clean, 3-5 amber, 6-8 orange, 9+ red, capped at 3.
  Rendered as a left border stripe plus a `3d` / `61d` pill.
- Column header gets an `N aging` badge that toggles the stack down to only the
  late cards. Per column, independent of the existing per-column sort.

### GOTCHA that shaped the design: the stage stamps mostly do not exist
Queried the live IndexedDB blob before trusting the model. Result:
`quote_sent` 13 cards / **0** with `quoteSentAt`; `invoiced` 31 cards / **7**
with `invoicedAt`. A strict per-stage clock would have lit up exactly one badge
on the whole board and looked broken.

Fix: `AGE_ANCHORS` is a **chain**, not a field. Stage stamp, then `updatedAt`,
then `createdAt`. `cardAge` returns `{days, exact}` and an inferred age renders
as `~5d` with a tooltip saying it was measured from the last update, so it can
never be misread as a real quote date. Cards moved through the board from now
on get the real stamp and lose the tilde.

**RULE: before building anything that reads a timestamp field, count how many
live records actually have it.** A feature keyed to a field the backlog never
populated is a feature that ships looking dead.

### Also
- `ServiceOrderPanel.tsx`: "Requested work" block in the dark header, shown only
  at `draft`/`quote_sent`, sourced `description || notes`. The scope was
  otherwise buried below the fold.
- Pending Completion card copy corrected: it now covers approved-but-not-yet-
  dispatched, so "In the field" was wrong.

### Files
- `solarflow-dashboard/src/components/Billing.tsx` (columns, aging, exports)
- `solarflow-dashboard/src/App.tsx` (`renderServiceOrder(backView)`, billing overlay)
- `solarflow-dashboard/src/components/ServiceOrderPanel.tsx` (requested-work block)
- `solarflow-dashboard/src/__tests__/billingColumns.test.ts` (NEW, 11 tests)

before push: New `2 aging`, Quote Sent `10 aging`, Invoiced `4 aging`; toggling
Quote Sent's badge cut the stack 13 to 10 and back; Create Quote opened the

Note: `TIER_STYLE` needed an explicit `0` entry. TS will not narrow

as an implicit-any error. Cheaper to carry an empty tier-0 row than to cast.

## Deploy 4: aging on all 7 billing columns + age sort (a22e1d4)

Commit `a22e1d4`, live `v1.7.6.0+a22e1d4.1785284103703`, builtAt
2026-07-29T00:15:03Z. Bundle-verified on `assets/Billing-C7wyBpBb.js`.
(`7eb0399` in between was the catalog refresh only.)

### Markers on every column
`AGE_ANCHORS` went from `Partial<Record<...>>` to a **total** `Record`, so the
three columns that previously had no clock now have one:

| column | anchor | what "old" means |
|---|---|---|
| `pending` | `quoteApprovedAt` -> `contractorSentAt` | how long the contractor has held it |
| `paid` | `clientPaidAt` | client paid, contractor/expenses still unsettled |
| `costs_covered` | `costsCoveredAt` | time since close-out |

Each keeps the `updatedAt` -> `createdAt` fallback and the `~` inexact prefix.

**GOTCHA, chain order per column is load-bearing.** A `paid` card with no
`clientPaidAt` must fall back to `updatedAt`, NOT to `invoicedAt`. Reaching
back to an earlier stage's stamp would report that stage's age as `exact` and
silently lie. Pinned by "does not let a later stage read an earlier stage's
stamp as exact".

### Age sort, most critical first by default
Two options added to the per-column dropdown: `age_desc` "Aging, Most Critical
First" and `age_asc` "Aging, Newest First".

Deliberately NOT added to `lib/jobSort.ts`: the anchor depends on which column
the card sits in and `sortJobsBy` has no column argument. Billing owns
`sortByAge` + `BILLING_SORT_OPTIONS` and delegates every other option to
`sortJobsBy` unchanged, so the Service Orders board is untouched.

Columns now DEFAULT to `age_desc` (was `none`). A marker you have to scroll to
find defeats the purpose. Saved per-column prefs in
`solarops_billing_col_sort` still win, so this only affects unset columns.

**GOTCHA in the ascending direction:** a card with no measurable age must sink
to the bottom in BOTH directions. Treating null as 0 would make "newest first"
lead with cards that merely have no date, burying the genuinely newest. Hence
the partition (dated, then undated) rather than a sentinel.

### Verified live on dev before push
Descending order held in every column: New 61,3 - Quote Sent 14,14,5,5 -
Pending 47,29,28,28 - Invoiced 46,46,46,34 - Paid 46,46,39,13. Flipping Quote
Sent to ascending reordered to 5,5,5. Build green, 315/315 tests.

### Open concern, NOT fixed (user asked for all columns explicitly)
`costs_covered` is the closed-out column: nothing is wrong with an old card
there, so its markers are pure noise and every closed order eventually goes
red. Same argument is weaker but real for `paid`. Flagged to the user with an
offer to drop `costs_covered` from `AGE_ANCHORS`, which is a one-line revert.

### Follow-ups
- `/snap-ui` NOT re-run for a22e1d4. `billing-kanban.png` now shows the old
  2-column-marker board and default sort. Re-capture next deploy.
